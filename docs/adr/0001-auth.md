# 0001. Auth with a JWT in an httpOnly cookie and argon2

Date: 14 November 2026. Status: accepted.

## Context

Login for a small family, maybe more users later. API and web are served from the same domain behind Caddy (`/api` and `/`). No email provider has been chosen yet (hole 6).

## Decision

- Passwords are hashed with argon2id (`@node-rs/argon2`: prebuilt binaries, no build tools needed in Docker)
- Login sets a signed JWT in a cookie: `httpOnly`, `Secure` in production, `SameSite=Lax`, `Path=/api`
- The token lives 7 days
- The JWT holds only the user id. Group access is checked in the database on every request
- The signing secret is `JWT_SECRET` in `.env`
- `POST`, `PUT`, `PATCH` and `DELETE` requests must have an `Origin` header matching the app's own origin. `SameSite=Lax` alone does not stop other subdomains of the same site
- Password reset waits until an email provider is chosen

## Why

- JavaScript cannot read an httpOnly cookie, so an XSS bug cannot steal the token. localStorage can be read
- Same domain means no CORS and no third-party cookies
- A JWT needs no session table. The downside is that a token cannot be revoked before it expires, so the lifetime stays short

## Rejected

- Sessions in the database: more code now. Can be added if we need to log out devices
- bcrypt: older and weaker than argon2id
- Auth services (Auth0, Clerk): external dependency and personal data at a third party
